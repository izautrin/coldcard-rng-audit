## Кратко

Ошибка конфигурации ГСЧ в партии прошивок Coldcard (`MICROPY_HW_ENABLE_RNG=0`)
привела к тому, что seed-фразы генерировались **программным псевдослучайным
генератором** вместо аппаратного TRNG. Эффективная энтропия ключей упала с 256
до ~**19–20 бит** — диапазона, перебираемого на одной потребительской видеокарте.

Независимый on-chain анализ реконструировал масштаб последовавшей кражи.

| Метрика | Значение |
|---|---|
| Восстановлено seed кошельков (потолок независимого перебора) | **~2,052** |
| Идентифицировано уникальных адресов жертв | **35,189** (все опустошены) |
| **Чистая кража (фактический ущерб, TX-graph)** | **~5,080 BTC ≈ $399M** |
| Валовый периметр (средства, прошедшие через ключи) | ~10,950 BTC ≈ $861M |
| Срок жизни уязвимости (первая on-chain кража → последняя) | **5+ лет (июль 2021 → авг 2026)** |
| Тихая эксплуатация до публичного раскрытия | **27+ месяцев** |
| Затронутая прошивка | Mk3 4.0.1–4.1.9 · Mk4 5.0.0–5.5.1 |
| Исправлено в | **4.2.0 / 5.6.0** |

> **Честно о цифрах:** *чистая кража (~$399M)* — защитимая величина фактического
> ущерба из анализа графа транзакций. *Gross (~$861M)* — суммарный объём, прошедший
> **через** ключи (включает внутреннюю прокрутку сдачи и **не** равен ущербу).
> В качестве заголовочной цифры корректнее приводить Net.

## Уязвимость (технически, высокий уровень)

- Сборочный флаг отключил путь аппаратного TRNG для процедуры генерации seed.
- Seed деривировались из программного ГСЧ с малым внутренним состоянием
  (семейство Yasmarang), эффективная энтропия которого в этом пути ~19–20 бит.
- При такой малой энтропии всё пространство ключей перебирается на обычных GPU
  за минуты-часы, что позволяет атакующему регенерировать seed жертв и их адреса.
- Дефект затронул *источник энтропии*, а не эллиптическую/деривационную математику;
  стандартные BIP-39/BIP-32/BIP-84 кошельки на этих seed полностью деривируемы.

Этот класс проблемы также публично отмечался третьими сторонами (напр. Galaxy
Research, BlockSec). Настоящий репозиторий — **независимая** реконструкция, которая
приходит к существенно большему масштабу за счёт (а) исчерпывающего восстановления
популяции seed и (б) трассировки change-/глубоко-деривированных адресов, которые
исследования только по спискам адресов пропускают.

## Объём и метод (высокий уровень)

- GPU-перебор восстановления уязвимой популяции seed до практического потолка.
- Деривация адресов по стандартным путям и в глубину для перечисления адресов жертв.
- On-chain forensics по балансам и графу транзакций (100% покрытие адресов) для
  разделения **внутренней прокрутки сдачи** и **внешних депозитов** и расчёта *Net*.
- Картирование хабов консолидации и multi-hop трассировка «следуй за деньгами» с
  моделью **haircut-taint** для оценки, сколько украденного BTC ещё лежит on-chain
  vs. обналичено через сервисы.

Полная методология и производные датасеты передаются **приватно** правоохранительным
органам и блокчейн-форензик партнёрам по запросу.

## Для затронутых пользователей

1. Если устройство работало на Mk3 `4.0.1–4.1.9` или Mk4 `5.0.0–5.5.1`, считайте
   **каждый** seed, сгенерированный на нём, скомпрометированным (включая paper wallets).
2. Сгенерируйте новый seed на исправленной прошивке (**4.2.0+ / 5.6.0+**), идеально —
   с dice-roll энтропией и/или BIP-39 passphrase.
3. Немедленно переведите все средства на новый кошелёк.
4. **Не отправляйте никакие суммы на старые адреса.** On-chain данные указывают, что
   адреса жертв всё ещё мониторит автоматический sweeper; новые депозиты под угрозой.

### Что НЕ в репозитории
Чтобы не помогать копикэтам против ещё не восстановленных кошельков и не навредить:

- ❌ Нет восстановленных seed-фраз, значений PAD/SKIP и констант ГСЧ.
- ❌ Нет реализации перебора и точных параметров поиска.
- ❌ Нет списка «кошельков с украденным» по parked-средствам (haircut-трассировка
  даёт false positives — публично назвать адрес держателем украденного можно ошибочно
  задев невиновного; эти данные — только для LE).
- ❌ **Нет персональной атрибуции ответственности конкретным лицам.** Корневая причина
  и любая персональная атрибуция — вопросы независимой верификации и компетентных
  органов, а не этого разбора.

Полный доказательный пакет (графы транзакций, taint-анализ, SHA-256 chain-of-custody)
предоставляется правоохранительным органам / форензик-фирмам по запросу.
